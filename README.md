# Wishlist подарков на день рождения Темы

Минимальный и аккуратный MVP-проект для семейного списка подарков.

## Что умеет проект

- Показывает фиксированный список подарков в таблице.
- Позволяет ввести имя и забронировать подарок.
- После бронирования подарок становится недоступен для других.
- Показывает имя человека, который забронировал подарок.
- Сохраняет данные в локальной SQLite-базе между перезапусками.
- Защищает от двойного бронирования на сервере (через условное обновление записи).

## Стек и почему он выбран

Используется **Node.js + Express + SQLite (sqlite3)**.

Почему это лучший вариант для данного MVP:

- минимум файлов и зависимостей;
- простой запуск локально;
- надежное хранение в одном файле базы;
- легко читать и поддерживать без оверинжиниринга.

## Запуск проекта (точные команды)

Требуется Node.js 18+ (рекомендуется 20 LTS).

1) Установить зависимости:

```bash
npm install
```

2) Инициализировать БД / сиды:

```bash
# отдельная команда не нужна:
# таблица gifts, триггеры и стартовые данные создаются автоматически при старте сервера
npm start
```

3) Локальный запуск:

```bash
npm start
```

4) Открыть сайт:

```text
http://localhost:3000
```

## Полезные команды

```bash
# Запуск в режиме разработки (автоперезапуск)
npm run dev

# Проверить, что API отвечает списком подарков
curl http://localhost:3000/api/gifts
```

## Переменные окружения

Проект использует минимум env-настроек:

- `PORT` — порт HTTP-сервера (по умолчанию `3000`).

Пример:

```bash
PORT=8080 npm start
```

## Деплой (минимальный production-план)

1. Установить Node.js 18+ на сервере.
2. Скопировать проект и выполнить `npm ci`.
3. Запустить `npm start` под process manager (например, systemd или pm2).
4. Убедиться, что директория `data/` доступна на запись приложению.
5. (Опционально) поставить reverse proxy (Nginx/Caddy) перед Node.js.

Важно: SQLite хранится в локальном файле `data/wishlist.db`, поэтому для production нужно
обеспечить постоянное хранилище тома/диска.

## Примечания

- Начальный список содержит 10 подарков.
- База `data/wishlist.db` создается автоматически при первом запуске.
- Начальные подарки добавляются только при пустой таблице (без дублирования при рестарте).
- Сервер валидирует имя бронирующего (2–80 символов), а БД дополнительно защищает от
  перезаписи уже занятого подарка.

## Ограничения MVP

- Нет аутентификации и истории изменений (кто/когда бронировал).
- Нет отмены брони через UI.
- SQLite подходит для небольшого семейного сценария; для высокой нагрузки лучше перейти на
  PostgreSQL и добавить миграции.

## Быстрая ручная проверка

1. Откройте `http://localhost:3000`.
2. Введите имя в поле «Введите ваше имя».
3. Нажмите «Забронировать» у любого свободного подарка.
4. Убедитесь, что у этого подарка статус стал «Забронировано», а имя появилось в таблице.
5. Перезапустите приложение (`Ctrl+C`, затем снова `npm start`).
6. Обновите страницу и убедитесь, что бронь сохранилась.

## Что проверено (smoke-test)

Ниже зафиксировано ожидаемое поведение MVP:

- **Сценарий A. Открытие страницы**  
  Страница открывается, видны заголовок, поле ввода, таблица и колонки: №, название, цена,
  ссылка, статус, имя, действие.

- **Сценарий B. Успешная бронь**  
  После ввода имени и нажатия «Забронировать» подарок становится занятым, отображается имя, кнопка
  пропадает.

- **Сценарий C. Ошибка при пустом имени**  
  При пустом имени бронь не выполняется, показывается понятная ошибка.

- **Сценарий D. Ошибка при имени из пробелов**  
  Имя из пробелов обрезается до пустого и отклоняется с понятной ошибкой.

- **Сценарий E. Повторная бронь занятого подарка**  
  При конкуренции побеждает только первый успешный запрос, второй получает конфликт (409) и
  понятное сообщение.

- **Сценарий F. Сохранение данных**  
  После перезапуска данные о бронировании сохраняются в `data/wishlist.db`.

- **Сценарий G. Ссылка на маркетплейс**  
  Ссылка открывается в новой вкладке (`target="_blank"`, `rel="noopener noreferrer"`), текущее
  состояние страницы не теряется.

- **Сценарий H. Мобильный экран**  
  На узком экране таблица остается читаемой (горизонтальный скролл контейнера, уменьшенные
  отступы/шрифты), интерфейс не «ломается».
